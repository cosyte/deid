"@cosyte/deid": patch
---

The FHIR adapter now replaces every element id, so free text a sender put in an element's `id` no longer reaches the output.

- **What changed, on purpose.** This changes the default output for every input that carries an element id. Before, the `id` of an element (`Observation.code.id`, a `Coding`, a backbone, a `Bundle.entry`, an extension at any depth) and a primitive's `_`-sibling `id` (`Observation._status.id`, the `_state.id` of a part a reduced `Address` keeps) were passed through unchanged and only counted in `unexaminedResiduals`, under every profile. Now each is replaced the way a resource's logical id is, in the same table: the same id gets the same replacement throughout one call, a per-call sequence number under Safe Harbor and a keyed surrogate (flagged as a re-identification code) under a policy that pseudonymizes or hashes the medical record number category. A policy with any other transform for that category removes every element id. Each replacement has a manifest row at its locus, with no value. An element id that is an object or a list is removed and recorded. The `actionId` of a `relatedAction` in a `RequestGroup` or a `PlanDefinition` names an action's element id, so it is replaced by the same value and the link still resolves. With transform labels on, a resource whose element ids were replaced is labeled.
- **Why replaced rather than removed.** R4 gives an element id no meaning outside the document, so removal would be as safe. Replacing it keeps the `relatedAction` links working and keeps the output's structure the same as the input's.
- **What a caller sees change.** The output carries a replacement where it carried an element id, the manifest has one more row per element id, and `unexaminedResiduals` no longer names an element id. A reference to an element id written anywhere but an `actionId` (a `contentReference`, a `TestScript` fixture id) no longer resolves. The public type `FhirEditKind` gains a member, `primitive-id`: code that switches over every member of it must handle the new one. No call needs editing.
