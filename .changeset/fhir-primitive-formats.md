"@cosyte/deid": patch
---

The FHIR adapter now blocks a primitive that does not fit the format FHIR R4 defines for its type, so a name typed where a date, a status or an id belongs is removed.

- **What changed in the default output, on purpose.** Every primitive the pass keeps is checked against the format the R4 (4.0.1) definitions give its type: the pattern of a `code`, an `id`, a `date`, a `dateTime`, an `instant`, a `time`, a `uri`, a `url`, a `canonical`, an `oid`, a `uuid`, a `base64Binary`, an `integer`, a `positiveInt`, an `unsignedInt`, a `decimal` and a `boolean`, matched against the whole value, and the range of an integer kind (-2147483648 to 2147483647, which `positiveInt` and `unsignedInt` take from `integer`). Before, a value of the right JSON type was passed through whatever it held and counted in `unexaminedResiduals`, under every profile: a name in `effectiveDateTime` or `Observation.issued`, a `meta.versionId` with a space in it, a `Coding.code` with a leading space, an `integer` past its range, a `positiveInt` of 0. Now such a value is removed and recorded as a block at its own locus, with no value, at every depth, in choice elements, contained resources and `Bundle` entries, under Safe Harbor, the Limited Data Set and every other profile.
- **Required codes.** A `code` at an element R4 binds, required, to a value set R4 defines (`Encounter.status`, `Observation.status`, `Narrative.status`, `Quantity.comparator`, 338 elements across 210 value sets) must now be one of that set's codes, or it is removed and recorded the same way. Fourteen elements are bound to a value set the published definitions do not carry whole (the MIME types at `Attachment.contentType` and eleven others, `Money.currency`, `Composition.confidentiality`); there a code is held to the `code` format alone.
- **Read in linear time.** Each format is checked by a scan written from R4's pattern for the type and tested to accept exactly what the pattern accepts, never by compiling the pattern: a backtracking engine runs some of R4's patterns (the `base64Binary` one) in time exponential in a short value built to fail at its end. A value of any length is decided in time linear in its length.
- **One element by its definition's words.** `SampledData.data` must be decimal values, or `E`, `L` and `U`, separated by a single space, as R4 defines it; anything else there is removed and recorded.
- **Extensions.** An extension's `url` that is not a `uri` by R4's format (one with white space in it) is now removed and recorded at its locus (`Observation.extension[0].url`); before, it was kept. A `url` that is a `uri` is kept verbatim, as before. With `keepPatientAnimal` on, a part of a kept animal `Coding` that does not fit its type is removed and recorded.
- **A `_`-sibling beside a structure.** `@cosyte/fhir` drops a `_`-sibling written beside an element that is not a primitive (`"_code": { ... }` beside a `CodeableConcept`), so it never reached the output, but it had no manifest row. `deidentifyFhirJson` now records a blocked row at its locus (`Observation._code`), with no value. `FhirDeidOptions` and `FhirExtractOptions` gain `parseIssues`: a caller of `deidentifyFhir` or `extractFhirLoci` who passes the issues `parseResource` returned gets the same rows, and without it nothing changes.
- **Transform labels.** With `transformLabels` on, an element R4 requires that the pass removed for its format (`Encounter.status`) carries the Data Absent Reason in its place.
- **What stays the same.** A value that fits its type is kept exactly as before, and none of the committed FHIR fixtures changes. An empty value is left as it was. At a `date`, a `dateTime` or an `instant`, a calendar date the date rule reads is still decided by that rule, even at a precision R4 does not give the type (a day where an `instant` belongs). The format check stops only what a format rules out: a name that fits a `code`, an `id` or a `uri` (`Coding.code` of `Smith`) is still kept and counted in `unexaminedResiduals`, and the limitations page says what a caller can do about it. So is a `SampledData.data` made of numbers (`123 45 6789`), which fits R4's words for the element.
- **A `base64Binary` that fits its format passes this check unread.** Valid base64 at an `Attachment.data`, `Binary.data`, `Signature.data` or any other `base64Binary` fits its format, and this check does not decode it. It can hold a whole clinical note, a scanned form or an image with every identifier in it; the embedded-content entry of this release removes it by default.
- **What a caller changes.** Nothing is required. To get rows for dropped `_`-siblings from `deidentifyFhir`, pass `parseIssues`.
