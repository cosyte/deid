Keyed X12 surrogates now fit their elements, a C-CDA root the header replaced is replaced on every element carrying it, and X12 files before 00402 keep values holding a `U`.

- **Keyed X12 surrogates fit their fields.** Under a preset that pseudonymizes or hashes, an X12 surrogate used to be the whole 64-character digest, longer than `REF-02`, `TRN-02` and `SBR-03` (50 characters in 005010, 30 in 004010), `CLM-01` and `CLP-01` (38) and the name elements allow. It is now the digest cut to the element's maximum, read for the functional group's version: the 005010 maxima when `GS-08` names 005010 or later, the 004010 maxima otherwise. Each character kept is 4 bits, so `REF-02` keeps 200 bits in 005010 and `CLM-01` 152. For a billion distinct values under one key, the chance that any two share a cut surrogate is at most 3.9e-13 at the shortest length kept, 25 characters (100 bits: a name with a middle name, or a first name in 004010). The same value under the same key still gets the same surrogate in fields of one length, and its first characters in a shorter one, and a holder of the output still cannot compute it without the key. A position shorter than 20 characters (80 bits) gets no surrogate: a name with a prefix or a suffix, a postal code and every date are removed and recorded as `DEID_LOCUS_BLOCKED` instead. Free text a caller's redactor writes into `MSG-01`, `III-04`, `K3-01` or `NTE-02` is blocked when it is longer than the element.
- **`GenericLocus.maxLength`.** A new optional field: the most characters a position holds. The engine cuts a keyed surrogate to it (or blocks the value when it is under 20), writes a stand-in that does not fit in its shape as its bare sequence number, and blocks any other value it writes that does not fit. Only the X12 adapter sets it; a caller that does not set it sees no change.
- **C-CDA roots the header replaced.** A root the header replaced, because an `<id>` there carried it with no extension, is now replaced on every element that carries it as its `@root`, with an extension or without: another header `<id>`, the document's own `<id>` and `<setId>`, and a clinical body `<id>`. It takes the same replacement, recorded at the root's own position (`.../id@root`), and the extension beside it is decided as before. `CcdaEditKind` gains `"id-root"`.
- **The X12 repetition separator is read by version.** Before 00402, `ISA-11` is the standards identifier `U`, not a separator, so a value holding a `U` (a reference such as `BHT-03`, a service type code such as `UC`) is no longer removed. Where `ISA-12` cannot be read as a version, or `ISA-11` is a punctuation character, `ISA-11` is still read as the separator.

Outputs that move: an X12 interchange de-identified under a preset that pseudonymizes or hashes (the limited data set preset among them) whose keyed values sit in elements shorter than 64 characters, which now carry shorter surrogates or none; a C-CDA document whose header replaces a root that another element carries beside an extension; and an X12 interchange before 00402 with a `U` in a value its position keeps. A caller that stored 64-character X12 surrogates from an earlier release matches them to new output on the cut length. The limitations page names what this does not cover: the other adapters set no bound, so a keyed surrogate there is still written whole.
