The FHIR adapter now blocks a key FHIR R4 does not define, or a value of a shape it does not define, wherever it sits, so text a sender put there is removed rather than passed through.

- **What changed, on purpose.** This changes the default output for an input that carries such a key. Before, a key R4 does not define outside an extension (`Observation.zzNote`, `Observation.code.coding[0].zzNote`, a key in a backbone, an `Identifier`, `meta`, a contained resource or a `Bundle` entry, below a person resource's top level) was passed through unchanged and only counted in `unexaminedResiduals`, under every profile and with every option at its default. Now it is removed whole, whatever it holds, and recorded in the manifest as a block at its own position, with no value, at any depth of any resource or datatype. The element names come from the R4 (4.0.1) definitions of every resource and datatype. A key inside a reduced `Address` that the `Address` datatype does not define was removed by the reduction without a row; it now has one. No option keeps such a key.
- **The row names the key's position, never the key.** A key R4 does not define is text the sender chose, so a name or an identifier spelled as a key must not reach the manifest either. Its row writes `<withheld>` and the key's position among its parent's keys in place of the key: `{"resourceType":"Observation","status":"final","zzNote":"..."}` gives the row `Observation.<withheld>[2]`, and a key in the third place of a `Coding` gives `Observation.code.coding[0].<withheld>[2]`. That holds inside an extension too (`Observation.extension[0].<withheld>[1]` where a row used to read `Observation.extension[0].note`), on a kept animal code and in a reduced `Address`. A row at a key R4 does define keeps its name (`Observation.valueString`). A caller who matched a row by the unknown key's name matches it by its position now.
- **Values of a shape R4 does not define.** A value whose JSON type is not the one R4 defines at its position is removed whole the same way, with a blocked row at its own locus and no value: a primitive of another JSON type than R4 gives it, which is a number or a boolean where R4 puts a string (`"valueString": 987654321`, `"code": {"text": 42}`, an element `id` held as a number, which used to be replaced) and a string or a boolean where R4 puts a number, or a string or a number where it puts a boolean (`"valueBoolean": "yes"`, `"total": "3"`, `"value": "5"` in a `Quantity`), at every depth and in every choice element; a string, a number, a boolean or a `null` where a structure belongs (`"subject": "..."`, `"generalPractitioner": ["..."]`, `"contained": ["..."]`, a `Bundle` entry's `"resource": "..."`), a structure where a primitive belongs (`"status": { ... }`, a `HumanName` where R4 puts a string), a list where R4 puts one value, one value where R4 puts a list (`"identifier": { ... }`, `"note": { ... }`), and a `null` that pads no repeating primitive. The JSON type of each primitive comes from the same R4 definitions: a `boolean` is a JSON boolean, an `integer`, a `decimal`, a `positiveInt` and an `unsignedInt` a JSON number, and every other primitive a JSON string. Before, such a value was passed through and counted, passed through with no row at all (a number at `valueString`, a string at `valueBoolean`), or read item by item by the rule for its element. A caller who sent a single object where R4 puts a list, or a number as a string, loses it now.
- **Resources of a type R4 does not define.** A resource whose `resourceType` is missing or is not one R4 defines (an unknown name, the abstract `Resource` or `DomainResource`, a datatype's name) is removed whole, wherever it sits, with one blocked row at its locus and no value. Before, its type and the fields no rule reads (`implicitRules`, `language` and `meta.source` among them) reached the output. At the root the output is now `{}` and the row's locus is `<withheld>`, so the type the sender wrote reaches neither the output nor the manifest.
- **Rows for dropped primitive extensions.** An extension on a primitive's `_`-sibling (`_birthDate.extension`, `_code.extension`) is not written to the output, bar the ones on the `state` or `country` a reduced `Address` keeps. It used to leave no manifest row; now each one gets a blocked row at its own locus (`Patient._birthDate.extension[0]`), with no value. Beside a primitive the pass removes, the primitive's own row still covers it.
- **What a caller sees change.** For an input with such a key, value or resource, the output no longer carries it, the manifest has one more blocked row for each (one that names the position, not the key, for a key R4 does not define) (or one blocked row in place of the rows a rule wrote inside it), and `unexaminedResiduals` no longer names the positions under it. For an input with a primitive extension the output does not carry, the manifest has one more blocked row per extension. A conformant input with no primitive extension the output drops gives the same output, manifest and residuals as before. Nothing in the API changed, so no call needs editing.
