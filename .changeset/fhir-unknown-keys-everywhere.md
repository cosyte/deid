The FHIR adapter now blocks a key FHIR R4 does not define wherever it sits, so free text a sender put under such a key is removed rather than passed through.

- **What changed, on purpose.** This changes the default output for an input that carries such a key. Before, a key R4 does not define outside an extension (`Observation.zzNote`, `Observation.code.coding[0].zzNote`, a key in a backbone, an `Identifier`, `meta`, a contained resource or a `Bundle` entry, below a person resource's top level) was passed through unchanged and only counted in `unexaminedResiduals`, under every profile and with every option at its default. Now it is removed whole, whatever it holds, and recorded in the manifest as a block at its own locus, with no value, at any depth of any resource or datatype. The element names come from the R4 (4.0.1) definitions of every resource and datatype. Every key of a structure where R4 puts a primitive (`"status": { ... }`) is removed the same way, and a resource of a type R4 does not define (or with no `resourceType`) keeps only what every resource carries: `id`, `meta`, `implicitRules`, `language`, `text`, `contained`, `extension` and `modifierExtension`. A key inside a reduced `Address` that the `Address` datatype does not define was removed by the reduction without a row; it now has one. No option keeps such a key.
- **Rows for dropped primitive extensions.** An extension on a primitive's `_`-sibling (`_birthDate.extension`, `_code.extension`) is not written to the output, bar the ones on the `state` or `country` a reduced `Address` keeps. It used to leave no manifest row; now each one gets a blocked row at its own locus (`Patient._birthDate.extension[0]`), with no value. Beside a primitive the pass removes, the primitive's own row still covers it.
- **What a caller sees change.** For an input with such a key, the output no longer carries it, the manifest has one more blocked row per key, and `unexaminedResiduals` no longer names the positions under it. For an input with a primitive extension the output does not carry, the manifest has one more blocked row per extension. An input with neither gives the same output, manifest and residuals as before. Nothing in the API changed, so no call needs editing.
