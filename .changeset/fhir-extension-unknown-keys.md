The FHIR adapter now blocks every key inside an extension other than its url, id and nested extensions, so free text under a key such as `note` is removed rather than passed through.

- **What changed, on purpose.** This changes the default output for an input that carries such a key. Before, a key R4 does not define on an extension (a `note` or `comment` beside the `url`, any name) was passed through unchanged and only counted in `unexaminedResiduals`, under every profile and with every option at its default. Now it is removed and recorded in the manifest as a block at its own locus (`Observation.extension[0].note`), with no value, exactly as an extension's `value[x]` is: in an `extension` and a `modifierExtension`, at any depth, on every resource. A `url` or an `id` on an extension that is not a single string is removed the same way. An extension on the `_`-sibling of the `state` or `country` a reduced `Address` keeps was passed through whole; its `value[x]` and unknown keys are now removed and recorded too, and its `url` and `id` stay. With `keepPatientAnimal` on, a kept animal `Coding` whose `userSelected` is not a boolean (a string or a number) has that `userSelected` removed and recorded, and an unknown key on the `patient-animal` extension or one of its parts is removed.
- **What a caller sees change.** For an input with such a key, the output no longer carries it, the manifest has one more blocked row per key, and `unexaminedResiduals` has one fewer position per string the key held. An input without one gives the same output, manifest and residuals as before. An unknown key outside an extension is unchanged: removed on a person resource's own top level, passed through and counted elsewhere. Nothing in the API changed, so no call needs editing.
