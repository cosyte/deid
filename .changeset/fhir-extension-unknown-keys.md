"@cosyte/deid": patch

The FHIR adapter now blocks every key inside an extension other than its url, id and nested extensions, so free text under a key such as `note` is removed rather than passed through.

- **What changed, on purpose.** This changes the default output for an input that carries such a key. Before, a key R4 does not define on an extension (a `note` or `comment` beside the `url`, any name) was passed through unchanged and only counted in `unexaminedResiduals`, under every profile and with every option at its default. Now it is removed and recorded in the manifest as a block at its own locus (`Observation.extension[0].note`), with no value, exactly as an extension's `value[x]` is: in an `extension` and a `modifierExtension`, at any depth, on every resource. A `url` or an `id` on an extension that is not a string (a number, a boolean, an object, a list) is removed the same way. An extension on the `_`-sibling of the `state` or `country` a reduced `Address` keeps was passed through whole; its `value[x]` and unknown keys are now removed and recorded too, and its `url` and `id` stay. A `state` or `country` a reduced `Address` keeps that is not a string (an object, a list, a number, a boolean) was passed through whole on a person resource; it is now removed and recorded at its own locus (`Patient.address.state`), and a swept `Address` carrying one is removed whole, as one carrying an object there already was. With `keepPatientAnimal` on, a kept animal `Coding` whose `userSelected` is not a boolean (a string or a number) has that `userSelected` removed and recorded, and an unknown key on the `patient-animal` extension or one of its parts is removed. A primitive's `_`-sibling that arrived as something other than an object (a string, a number, a boolean or a `null`, as in `"_status": "..."` or an extension's `"_url": "..."`, or a list in the slot of a repeating primitive) was written back unchanged and not counted, on every resource and at every depth, the kept `state` and `country` of an `Address` and the `patient-animal` extension included. Now every primitive the pass writes is built from its value, its element `id` and the extensions the pass kept, so that text is removed and recorded as a block at the `_`-sibling's own locus (`Observation._status`), with no value. A `null` written as a primitive's value where FHIR JSON defines none (`"status": null`) is no longer written back either.
- **What a caller sees change.** For an input with such a key, part or `_`-sibling, the output no longer carries it, the manifest has one more blocked row per key, part or `_`-sibling, and `unexaminedResiduals` has one fewer position per value the key or part held. An input without one gives the same output, manifest and residuals as before. An unknown key outside an extension is unchanged: removed on a person resource's own top level, passed through and counted elsewhere. An element `id` that is a string is unchanged too: passed through and counted. Nothing in the API changed, so no call needs editing.
