# scripts/phi-allow-list.txt
#
# PHI-scan allow-list: the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit. Byte-strict wire formats cannot carry an
# inline `# synthetic: true` header (the header segment must be the first bytes),
# so this allow-list is the synthetic-fixture declaration mechanism, the same
# approach every sibling `@cosyte/*` parser uses.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>          synthetic person-name word, matched case-insensitively
#   DOB <value>           synthetic date of birth (normalize as your detector does)
#   ID <value>            synthetic id matching an SSN / MRN / member-id shape
#   EMAILDOMAIN <domain>  reserved / test email domain that is allowed to appear
#
# NOTE: the STARTER scanner only actively consumes EMAILDOMAIN (its floor is
# SSN + email shapes). NAME / DOB / ID entries are loaded and ready for the
# structured, field-level detectors you MUST add to scripts/phi-scan.ts before
# relying on this as a real PHI gate: see the STARTER banner in that file.
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act, never silent.

# --- This package's own published contact address ---
# `package.json`'s `author` field carries a mailbox at this domain. It is registry
# metadata that ships in every published tarball and is already public on the npm
# page; it is a company mailbox, not a person's, and it is NOT patient data.
#
# The ADDRESS ITSELF IS DELIBERATELY NOT WRITTEN OUT HERE. This file sits inside a
# scan root, so spelling it out would make THIS file red whenever the declaration
# below is struck -- and striking that declaration is exactly how the scanner's
# own positive control proves it opened `package.json`. A control that reds on two
# files cannot tell which one it read.
#
# It surfaced only when all mode began reading the bytes git carries: package.json
# sits outside every scan root, so no route had ever opened it. The declaration is
# the honest answer rather than narrowing the sweep back to where it could not see
# the file.
#
# ▶ THE COST, STATED RATHER THAN HIDDEN: an EMAILDOMAIN entry is GLOBAL and
# ROUTE-BLIND. This one stops the floor firing on ANY address at cosyte.com, in
# any file, on every route -- not just on the manifest. That is the mechanism this
# allow-list has, and the trade is accepted deliberately: a real patient address
# would not be at our own corporate domain, and the alternative (a per-path
# exemption) is the whole-file bypass, which silences every check for that file.
EMAILDOMAIN cosyte.com
